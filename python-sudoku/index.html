Build a Sudoku Game in Python

You already know Python basics. This isn't a copy-the-code tutorial — it's a series of challenges. Each one gives you a goal, a way to think it through, and a way to know when you've nailed it. You write the code. The hints and solutions are there if you get stuck, but reach for them last.

This is what you're going to build.

How to think about a project this big

A finished game looks like a wall of code, and that's intimidating. The trick pros use is simple: you never build the whole thing at once. You break it into pieces small enough that each one is obvious, get each piece working on its own, then snap them together.

The single most important idea in this whole project:

Separate the brain from the face. The brain is the pure Sudoku logic — a grid of numbers and the rules about them. It doesn't know pygame exists. The face is the pygame window that draws the brain and takes clicks. Build and test the brain first, in the plain terminal, where bugs are easy to see. Only then put a face on it.

Why does that matter? Because if your solver is broken, you want to discover that by print()-ing a grid — not by squinting at pixels. Every challenge below respects that split: challenges 1–5 are pure brain (no window at all), and 6 onward add the face.

Your toolbox for getting unstuck

  • Read the goal, then look away. Try to picture the steps before you write anything.
  • Test the smallest thing. Wrote a function? Call it once with a known input and print the result before moving on.
  • Only open a hint when you're truly stuck — and open the "Reference solution" only to check yourself, not to copy.

Setup · pygame · the game loop

Setup & a blank window

Get Python and pygame installed, and open an empty window that stays open until you close it.

Think it through

Before any Sudoku logic, you need proof your tools work. Installing a library and opening a window is the "hello world" of game programming. A pygame program has a shape you'll reuse all project long: set up once, then loop forever — check for events, draw, repeat — until the user quits.

  1. Confirm Python 3 runs from your terminal (python3 --version).
  2. Install pygame with pip. If you're not sure of the command, that's a great thing to look up.
  3. Open a window. Then ask: why does a game need a loop? What would happen without one?
Acceptance criteria
  • Running your file opens a window (any size) that doesn't instantly vanish.
  • Clicking the window's close button actually closes it and ends the program cleanly.
  • You can explain, in your own words, what the "game loop" is doing every frame.
Test it
  • Run it. Window appears? Good. Close it — does the terminal return to a prompt without an error?
  • Temporarily delete the event loop. Run again. What happens now? (Then put it back.)

Stuck? Open these one at a time — challenge yourself to use as few as you can.

Hint 1 — where to look

Two separate jobs here: install the library, then run a minimal program. To install a Python package you use pip from the terminal (not from inside Python). To keep a window open, remember that a program ends the instant it runs out of lines — so you need something that keeps it going.

Hint 2 — the approach

Install once from the terminal: pip install pygame (or pip3).

Every pygame program needs these moves: pygame.init(), then pygame.display.set_mode((width, height)) to make the window. A while loop keeps it alive: each pass, read events with pygame.event.get(); when you see an event of type pygame.QUIT, stop the loop and call pygame.quit(). After drawing each frame, pygame.display.flip() shows it.

Reference solution — check yourself 
import pygame

pygame.init()
screen = pygame.display.set_mode((540, 540))
pygame.display.set_caption("Sudoku")

running = True
while running:
    for event in pygame.event.get():
        if event.type == pygame.QUIT:
            running = False

    screen.fill((24, 27, 34))   # dark background
    pygame.display.flip()       # show what we drew

pygame.quit()

Why the loop? Without it, the program reaches the end and exits instantly — the window flashes and disappears. The loop keeps the program alive and, every pass, re-checks "did anything happen?" and re-draws the screen.

Data structures · lists of lists

Represent the board

Decide how a Sudoku grid lives in memory, and print one to the terminal so you can read it.

Think it through

This is a design decision, and it shapes everything after it. A Sudoku board is 9 rows of 9 numbers. What Python structure naturally holds "rows of things"? How will you represent an empty cell — a number you'll never confuse with a real answer is ideal.

Once you've picked a structure, ask: to read the value in row 3, column 5, what would you type? If that's awkward, your structure is wrong. Get this right and the rest of the project gets easier.

Acceptance criteria
  • A board is stored in one variable you can pass around.
  • You can read and change a single cell by its row and column.
  • You can print the board so a human can read it as a 9×9 grid (empty cells shown as a dot or space).
Test it
  • Print a hand-typed board. Do the rows line up as a 9×9 grid?
  • Set row 0, column 0 to the number 5, print again. Did exactly one cell change?

Stuck? Open these one at a time — challenge yourself to use as few as you can.

Hint 1 — where to look

You want a container that holds "rows of things," where each row is itself a container of 9 numbers. Python has a type that nests inside itself perfectly for this. And for "empty," pick a value that can never be confused with a real answer (1–9).

Hint 2 — the approach

A list of lists is the natural fit: the outer list is the rows, each inner list is 9 numbers. Use 0 for an empty cell — real answers are 1–9, so 0 can never be mistaken for one.

Then board[row][col] reads or sets any cell. To print nicely, loop over the rows and build a string for each; swap 0 for a . so gaps are visible.

# 0 means "empty". Real answers are 1-9.
board = [
    [5, 3, 0,  0, 7, 0,  0, 0, 0],
    [6, 0, 0,  1, 9, 5,  0, 0, 0],
    [0, 9, 8,  0, 0, 0,  0, 6, 0],
    [8, 0, 0,  0, 6, 0,  0, 0, 3],
    [4, 0, 0,  8, 0, 3,  0, 0, 1],
    [7, 0, 0,  0, 2, 0,  0, 0, 6],
    [0, 6, 0,  0, 0, 0,  2, 8, 0],
    [0, 0, 0,  4, 1, 9,  0, 0, 5],
    [0, 0, 0,  0, 8, 0,  0, 7, 9],
]

def print_board(board):
    for row in board:
        line = ""
        for num in row:
            line += (str(num) if num != 0 else ".") + " "
        print(line)

print_board(board)
print(board[0][0])   # -> 5
board[0][2] = 4      # fill one empty cell

An empty grid is handy too: [[0] * 9 for _ in range(9)] builds nine separate rows of nine zeros. (Watch out: [[0]*9]*9 looks the same but reuses one row — a classic trap.)

Logic · the three Sudoku rules

The rules: is this move legal?

Write a function that answers one question: can number n go in a given cell without breaking Sudoku's rules?

Think it through

This one function is the heart of the entire game — the solver, the generator, and the mistake-checker all lean on it. Sudoku has exactly three rules. A number is allowed only if it does not already appear in:

  1. its row,
  2. its column, and
  3. its 3×3 box.

Rows and columns are easy to loop over. The 3×3 box is the tricky part: given a cell at (row, col), which box is it in, and where does that box start? Play with the numbers on paper: cell (4, 7) — what are the top-left coordinates of its box? See if a pattern with // 3 (integer division) falls out.

Acceptance criteria
  • is_valid(board, row, col, num) returns True or False.
  • It correctly rejects a number that repeats in the same row, column, or box.
  • It checks a cell that is currently empty (you're asking "could this go here?").
Test it
  • On the board from Challenge 1, is_valid(board, 0, 2, 5) → should be False (5 is already in row 0).
  • is_valid(board, 0, 2, 4) → should be True.
  • Find a number blocked only by the 3×3 box (not its row or column) and confirm it's rejected.

Stuck? Open these one at a time — challenge yourself to use as few as you can.

Hint 1 — where to look

There are three independent checks — row, column, box — and the number is only legal if it passes all three. The row and column are easy loops. Put your energy into the box: given a cell, can you figure out which 3×3 box it belongs to, and where that box starts?

Hint 2 — the approach

Row and column: loop i from 0 to 8 and check board[row][i] (the row) and board[i][col] (the column).

The box: the top-left corner is 3 * (row // 3), 3 * (col // 3). For (4, 7): 3*(4//3)=3 and 3*(7//3)=6 — so the box runs rows 3–5, columns 6–8.

Hint 3 — step by step
  1. Loop i 0→8: if board[row][i] == num or board[i][col] == num, return False.
  2. Compute box_row = 3 * (row // 3) and box_col = 3 * (col // 3).
  3. Loop r over box_row .. box_row+2 and c over box_col .. box_col+2: if any board[r][c] == num, return False.
  4. If nothing matched, return True.
Reference solution — check yourself 
def is_valid(board, row, col, num):
    # rule 1 & 2: not already in this row or this column
    for i in range(9):
        if board[row][i] == num or board[i][col] == num:
            return False

    # rule 3: not already in this 3x3 box
    box_row = 3 * (row // 3)
    box_col = 3 * (col // 3)
    for r in range(box_row, box_row + 3):
        for c in range(box_col, box_col + 3):
            if board[r][c] == num:
                return False

    return True   # passed all three rules

Why // 3 then * 3? Integer-dividing by 3 collapses 0,1,2 → 0 and 3,4,5 → 1 (which box you're in). Multiplying back by 3 gives the box's starting row/column. It's a rounding-down-to-the-nearest-3 trick.

Recursion · backtracking

Solve it with backtracking

Write a function that solves any solvable board by filling it in completely.

Think it through

This is the big-idea challenge. You can't "calculate" a Sudoku answer with a formula — you have to search. The technique is called backtracking, and once it clicks, you'll see it everywhere (mazes, puzzles, AI). The idea:

  1. Find the first empty cell. If there are none, the board is solved — success!
  2. Try putting 1 there. Is it valid (Challenge 2)? If yes, assume it's right and solve the rest of the board the same way.
  3. If that assumption leads to a dead end, undo it (set the cell back to 0) and try 2, then 3…
  4. If none of 1–9 work, this whole branch is impossible — go back and let the previous cell try its next number.

Notice step 2 says "solve the rest the same way" — a function that calls itself. That's recursion. The hard part isn't the code (it's short); it's trusting that the same function will handle "the rest of the board." Draw it out for a 2-cell example if you need to.

Acceptance criteria
  • solve(board) fills the board in place and returns True when solved.
  • It returns False for a board that has no solution.
  • Crucially: when a guess fails, the cell is reset to 0 (no leftover wrong numbers).
Test it
  • Solve the Challenge 1 board, then print it. Every cell 1–9, no zeros left?
  • Spot-check: does every row contain 1 through 9 exactly once? (A quick loop can verify.)
  • Feed it an impossible board (put two 5s in one row). Does it return False instead of hanging?

Stuck? Open these one at a time — challenge yourself to use as few as you can.

Hint 1 — where to look

Two ingredients. First, a tiny helper that finds the next empty cell (or reports there are none). Second, the solver calls itself to handle "the rest of the board." The mental hurdle isn't the code — it's trusting recursion. Try tracing it on a board with just two empty cells, on paper, until you believe it works.

Hint 2 — the approach

Write a helper find_empty(board) that returns the (row, col) of the first 0, or None if the board is full.

Then solve follows the four steps: if find_empty returns None, you're done. Otherwise try each num 1–9; when it's valid, place it and recurse; if the recursion fails, undo it and try the next number.

Hint 3 — step by step
  1. spot = find_empty(board). If it's None, return True.
  2. Unpack row, col = spot.
  3. For num in 1–9: if is_valid(board, row, col, num):
    • set board[row][col] = num
    • if solve(board) is True, return True
    • otherwise set board[row][col] = 0 (the crucial undo) and keep looping
  4. After the loop with no success, return False.
Reference solution — check yourself 
def find_empty(board):
    for r in range(9):
        for c in range(9):
            if board[r][c] == 0:
                return r, c
    return None   # no empties -> board is full

def solve(board):
    spot = find_empty(board)
    if spot is None:
        return True                 # nothing empty = solved!
    row, col = spot

    for num in range(1, 10):
        if is_valid(board, row, col, num):
            board[row][col] = num    # guess
            if solve(board):         # can the rest be solved?
                return True
            board[row][col] = 0      # no -> undo (backtrack)

    return False                     # 1-9 all failed here

The one line that makes it "backtracking" is board[row][col] = 0. Without that undo, failed guesses pile up and pollute the board. With it, the search cleanly explores every possibility and abandons dead ends.

Generate a full grid

Produce a complete, valid, random 9×9 solution — a different one each time you run it.

Think it through

To make puzzles, you first need full boards to carve them out of. Here's the clever part: you already wrote almost all of this in Challenge 3. Your solver fills an empty board — but it always tries 1, 2, 3… in the same order, so it always produces the same grid.

What single change would make it produce a random grid instead? Think about that "try 1–9 in order" loop. If the order were shuffled each time, where would that lead?

Acceptance criteria
  • A function returns a fully filled 9×9 board that obeys all Sudoku rules.
  • Running it twice gives two different boards.
Test it
  • Generate two grids, print both. Different? Both valid (rows/cols/boxes each hold 1–9 once)?
  • Generate ten in a loop without a crash.

Stuck? Open these one at a time — challenge yourself to use as few as you can.

Hint 1 — where to look

You already wrote almost all of this in Challenge 3. Your solver fills an empty board — but it always tries 1, then 2, then 3… in the same order, so it always builds the same grid. What one thing could you randomize so the finished grid comes out different each time?

Hint 2 — the approach

Start from an empty board ([[0]*9 for _ in range(9)]). Copy your solve function, but instead of for num in range(1, 10), build nums = list(range(1, 10)), call random.shuffle(nums), and loop over nums. Because the first choices are random, the whole solved grid comes out random.

Reference solution — check yourself 
import random

def full_solution():
    board = [[0] * 9 for _ in range(9)]

    def fill(board):
        spot = find_empty(board)
        if spot is None:
            return True
        row, col = spot

        nums = list(range(1, 10))
        random.shuffle(nums)          # <- the only real change
        for num in nums:
            if is_valid(board, row, col, num):
                board[row][col] = num
                if fill(board):
                    return True
                board[row][col] = 0
        return False

    fill(board)
    return board

Same backtracking engine as Challenge 3 — just fed its choices in random order. Reusing a working function instead of writing a new one is exactly the instinct to build.

Algorithms · uniqueness · difficulty

Turn it into a puzzle

Take a full solution and remove numbers to make a playable puzzle — with difficulty levels, and (the pro move) a guarantee that it has only one answer.

Think it through

A puzzle is just a full solution with holes punched in it. More holes = harder. So: pick cells at random and set them to 0. How many you remove becomes your difficulty setting.

But there's a subtle trap that separates a toy from a real Sudoku: a proper puzzle has exactly one solution. If you remove too much, the remaining clues might allow two different valid answers — which feels broken to a player. How could you check whether a board still has a unique solution? You have a solver… what if you taught it to count solutions instead of stopping at the first? Then only remove a number if the count stays at 1.

Acceptance criteria
  • A function returns a puzzle (with holes) and its full solution.
  • Easy/Medium/Hard remove different amounts, producing visibly different fill levels.
  • Stretch Every generated puzzle has exactly one solution.
Test it
  • Generate an Easy and a Hard puzzle; count the blanks in each. Hard has more?
  • Solve a generated puzzle — does it match the solution the generator handed back?
  • Stretch: after generating, count solutions of the puzzle. Always exactly 1?

Stuck? Open these one at a time — challenge yourself to use as few as you can.

Hint 1 — where to look

A puzzle is just a full solution with holes punched in it, so the removing part is easy — pick cells and set them to 0, and let "how many you remove" be your difficulty. The real thinking is the uniqueness catch: how could you check whether the puzzle still has only one answer? You built something in Challenge 3 that could be adapted to count answers instead of finding just one.

Hint 2 — the approach

Copy the full solution. Make a list of all 81 coordinates, shuffle it, and walk through it removing cells until you've removed N (N depends on difficulty).

For the uniqueness stretch: write count_solutions(board) — it's your backtracker, but instead of returning True on the first solve, it adds up how many complete fills exist (stop early once you've found 2 — you only care "one vs. more than one").

Hint 3 — step by step
  1. solution = full_solution(); copy it into puzzle.
  2. Build cells = [(r, c) for r in range(9) for c in range(9)] and shuffle it.
  3. Walk the shuffled cells, counting how many you've removed. For each cell (until you hit N):
    • save the current value, then blank the cell (set to 0)
    • stretch: if count_solutions(copy_of_puzzle) isn't exactly 1, put the saved value back (removing it broke uniqueness); otherwise count it as removed
  4. Return both puzzle and solution.
Reference solution — check yourself 
DIFFICULTY = {"Easy": 40, "Medium": 50, "Hard": 56}   # cells to remove

def count_solutions(board, limit=2):
    spot = find_empty(board)
    if spot is None:
        return 1
    row, col = spot
    total = 0
    for num in range(1, 10):
        if is_valid(board, row, col, num):
            board[row][col] = num
            total += count_solutions(board, limit)
            board[row][col] = 0
            if total >= limit:      # 2 is enough to know it's "not unique"
                break
    return total

def make_puzzle(difficulty="Medium"):
    solution = full_solution()
    puzzle = [row[:] for row in solution]          # deep-ish copy
    holes = DIFFICULTY[difficulty]

    cells = [(r, c) for r in range(9) for c in range(9)]
    random.shuffle(cells)
    removed = 0
    for r, c in cells:
        if removed >= holes:
            break
        saved = puzzle[r][c]
        puzzle[r][c] = 0
        if count_solutions([row[:] for row in puzzle]) != 1:
            puzzle[r][c] = saved   # removing it broke uniqueness -> undo
        else:
            removed += 1
    return puzzle, solution

Notice the pattern repeating: guess → check → undo if bad. It's the same backtracking instinct from Challenge 3, now used to remove clues safely. One good idea, reused three times.

Graphics · coordinates · drawing

Draw the board

Draw your 9×9 grid in the pygame window: the lines (with bold lines between boxes) and every clue number.

Think it through

The screen is a grid of pixels; your board is a grid of cells. Drawing is really just a translation between the two. If each cell is, say, 60 pixels wide, then cell (row, col) lives at pixel x = col * 60, y = row * 60. Get that mapping straight and everything else is detail.

  • Lines: you need 10 vertical and 10 horizontal lines. Which ones should be thick? (Every third one, to separate the 3×3 boxes.)
  • Numbers: for each non-zero cell, render the digit as text and place it centered in that cell's square.
  • This drawing happens inside the game loop, every frame — so the screen always reflects the current board.
Acceptance criteria
  • A visible 9×9 grid, with the four box-dividing lines noticeably thicker.
  • The clue numbers from a generated puzzle appear in the right cells.
  • Empty cells are simply blank.
Test it
  • Draw a puzzle you know. Do the numbers sit in the correct squares?
  • Count grid lines — 10 each way? Are the box separators heavier?

Stuck? Open these one at a time — challenge yourself to use as few as you can.

Hint 1 — where to look

The whole job is translating cell coordinates into pixel coordinates. If each cell is CELL pixels wide, then cell (row, col) starts at pixel x = col * CELL, y = row * CELL. For the lines, think about which ones separate the 3×3 boxes — those are the ones you want thicker.

Hint 2 — the approach

Draw lines with pygame.draw.line(screen, color, start, end, width). Loop i from 0 to 9; make the width 3 when i % 3 == 0, else 1.

For numbers: make a font once with pygame.font.SysFont("Arial", 34). Each frame, glyph = font.render(str(n), True, color) gives you an image of the digit; screen.blit(glyph, (x, y)) stamps it. To center it, offset by half the leftover space: x + (CELL - glyph.get_width()) // 2.

Hint 3 — step by step
  1. Fill the background: screen.fill((24, 27, 34)).
  2. Loop i 0→9. Draw one vertical line from (i*CELL, 0) to (i*CELL, 9*CELL) and one horizontal line the same way, using width 3 when i % 3 == 0 else 1.
  3. Loop every cell (r, c). If board[r][c] isn't 0, render it to a glyph and blit it centered in that cell.
  4. Call this function each frame inside the loop, just before pygame.display.flip().
Reference solution — the draw function 
CELL = 60          # pixels per cell
font = pygame.font.SysFont("Arial", 34)

def draw_board(screen, board):
    screen.fill((24, 27, 34))

    # grid lines: thick every 3rd line to mark the boxes
    for i in range(10):
        w = 3 if i % 3 == 0 else 1
        color = (120, 130, 150) if i % 3 == 0 else (58, 64, 78)
        pygame.draw.line(screen, color, (i * CELL, 0), (i * CELL, 9 * CELL), w)
        pygame.draw.line(screen, color, (0, i * CELL), (9 * CELL, i * CELL), w)

    # numbers, centered in their cells
    for r in range(9):
        for c in range(9):
            n = board[r][c]
            if n != 0:
                glyph = font.render(str(n), True, (233, 237, 245))
                x = c * CELL + (CELL - glyph.get_width()) // 2
                y = r * CELL + (CELL - glyph.get_height()) // 2
                screen.blit(glyph, (x, y))

Call draw_board(screen, board) every frame inside your loop, right before pygame.display.flip().

Events · mouse & keyboard input

Select a cell

Let the player click a cell to select it, and draw a highlight on the selected cell.

Think it through

Drawing was cells → pixels. Clicking is the reverse: pixels → cells. When the player clicks at pixel (mx, my), which cell is that? If a cell is 60 px, then col = mx // 60 and row = my // 60. Store that (row, col) as "the selected cell," and in your draw function, paint that one square a different color before drawing the lines.

As a nice touch, let the arrow keys move the selection too — how would you nudge the stored row/col by ±1?

Acceptance criteria
  • Clicking a cell selects it; the selected cell is visibly highlighted.
  • Clicking a different cell moves the highlight.
  • Arrow keys move the selection (bonus).
Test it
  • Click each corner. Does the highlight land on the corner cell (not one off)?
  • Press the arrow keys — does the selection walk around the grid?

Stuck? Open these one at a time — challenge yourself to use as few as you can.

Hint 1 — where to look

Drawing went cells → pixels. A click is the exact reverse: pixels → cells. If a cell is CELL pixels, then a click at (mx, my) lands in column mx // CELL and row my // CELL. Integer division does the "which cell" math for you.

Hint 2 — the approach

In the event loop, watch for event.type == pygame.MOUSEBUTTONDOWN. The click position is event.pos → (mx, my). Convert and store: selected = (my // CELL, mx // CELL).

In draw_board, if selected isn't None, draw a filled pygame.Rect in that cell's square before the grid lines so the lines stay on top. For arrow keys, nudge the stored row or column by ±1 (wrap with % 9).

Reference solution — selection 
# in the event loop:
if event.type == pygame.MOUSEBUTTONDOWN:
    mx, my = event.pos
    selected = (my // CELL, mx // CELL)     # pixels -> (row, col)

# in draw_board, before drawing the grid lines:
if selected is not None:
    r, c = selected
    rect = pygame.Rect(c * CELL, r * CELL, CELL, CELL)
    pygame.draw.rect(screen, (46, 84, 130), rect)   # highlight

# arrow keys (event.type == pygame.KEYDOWN):
if event.key == pygame.K_UP and selected:
    selected = ((selected[0] - 1) % 9, selected[1])
# ...down/left/right adjust the other index the same way

Using % 9 makes the selection wrap around the edges — a small touch that feels polished.

Input · protecting data

Type in numbers

Let the player type 1–9 into the selected cell, and clear it with 0 or Backspace — but never let them overwrite an original clue.

Think it through

Now the board becomes interactive. When a number key is pressed and a cell is selected, write that number into the board. Two design questions worth pausing on:

  1. How do you know which keys are 1–9? pygame gives key constants like pygame.K_1. Is there a pattern connecting the key to the digit it means?
  2. How do you protect the clues? The puzzle's original numbers must be permanent. You need to remember which cells came from the puzzle vs. which the player filled. What data structure would record "is this cell a fixed clue?" for all 81 cells?
Acceptance criteria
  • Pressing 1–9 with a cell selected writes that number into the cell.
  • Pressing 0 / Backspace / Delete clears the selected cell.
  • Original clues cannot be changed or erased.
Test it
  • Select an empty cell, type 7 — does a 7 appear? Type 3 — does it replace the 7?
  • Select a clue cell and mash number keys. Does it stay put?
  • Clear a cell you filled. Gone?

Stuck? Open these one at a time — challenge yourself to use as few as you can.

Hint 1 — where to look

Two questions to crack. (1) How do you know a pressed key is one of 1–9, and turn it into that number? The key constants aren't random — look at how they're numbered. (2) How do you stop the player editing an original clue? You'll need to remember, for all 81 cells, which ones came from the puzzle. What structure could store a True/False for every cell?

Hint 2 — the approach

The key constants are consecutive: pygame.K_1 through pygame.K_9. So if pygame.K_1 <= event.key <= pygame.K_9, the digit is event.key - pygame.K_0.

When you generate the puzzle, build a parallel 9×9 grid of True/False: given[r][c] = (puzzle[r][c] != 0). Before writing to a cell, check if not given[r][c]:.

Hint 3 — step by step
  1. Only act if a cell is selected — grab r, c = selected.
  2. Guard it: if not given[r][c]: (clues are off-limits).
  3. If pygame.K_1 <= event.key <= pygame.K_9, set board[r][c] = event.key - pygame.K_0.

Hint 1 — where to look

You already have the detector — is_valid from Challenge 2. The only wrinkle: a number that's already sitting in the cell will find itself and look like a duplicate. How could you test a placed number fairly, as if the cell were empty?

Hint 2 — the approach

Loop every cell. For a non-empty cell holding n: set that cell to 0, call is_valid(board, r, c, n), then set it back to n. If it wasn't valid, add (r, c) to a conflicts set. Lifting the number out first is what stops it from clashing with itself. Then in draw_board, color any cell in that set red.

Reference solution — finding conflicts 
def find_conflicts(board):
    bad = set()
    for r in range(9):
        for c in range(9):
            n = board[r][c]
            if n == 0:
                continue
            board[r][c] = 0                    # lift it out...
            if not is_valid(board, r, c, n):   # ...test fairly...
                bad.add((r, c))
            board[r][c] = n                    # ...put it back
    return bad

In draw_board: if (r, c) in conflicts: use red, elif given[r][c]: use white, else: use blue. Three colors, three meanings — instant, readable feedback.
